# Tayssir Froid — الموقع الرسمي

متجر إلكتروني بالجملة لقطع غيار الغسالات والثلاجات والمجمدات والمكيفات
وأدوات التبريد، موجَّه للتجار والصنايعية ومحلات قطع الغيار في المغرب.

هذه المرحلة (المرحلة 1) تضم: أساس مشروع Next.js، مخطط قاعدة البيانات
الكامل، وصفحات معاينة أساسية (الرئيسية، صفحة تصنيف، صفحة منتج) تجلب بياناتها
من قاعدة البيانات مباشرة. **لا توجد بعد** سلة شراء، صفحة إتمام طلب، أو لوحة
إدارة — هذه ضمن مراحل لاحقة بعد مراجعة هذه المرحلة والموافقة عليها.

## البنية التقنية

- **Next.js 16** (App Router) + **TypeScript** + **Tailwind CSS 4**.
- **PostgreSQL** (يُستهدف مشروع **Supabase** لاحقاً؛ الاتصال عبر
  `DATABASE_URL` مباشرة بحزمة [`postgres`](https://github.com/porsager/postgres)،
  وليس عبر supabase-js).
- تصميم عربي **RTL** بالكامل (`dir="rtl"` `lang="ar"`)، Mobile First.
- بيانات المنتجات والأسعار والمخزون **كلها في قاعدة البيانات**، ولا يوجد أي
  منتج أو سعر مكتوب داخل الكود.

## هيكلة قاعدة البيانات

الملفات المرجعية (Source of Truth) في `supabase/migrations/*.sql`، تُطبَّق
لاحقاً على مشروع Supabase الحقيقي عبر `supabase db push` أو بلصقها في SQL
Editor:

| الجدول | الغرض |
|---|---|
| `categories` | التصنيفات (تدعم تصنيفات فرعية عبر `parent_id`) |
| `products` | المنتجات: SKU، الأسعار، المخزون، الكمية الدنيا، درجة الزيادة |
| `product_variants` | المقاسات/الأنواع المختلفة لنفس المنتج |
| `product_images` | صور كل منتج |
| `orders` / `order_items` | الطلبات وتفاصيلها (المجموع النهائي يُحدَّد بعد تحديد عدد الكرطونات) |
| `order_status_history` | تاريخ تغيّر حالة كل طلب |
| `settings` | إعدادات عامة قابلة للتعديل لاحقاً من لوحة الإدارة (الحد الأدنى، ثمن التوصيل...) |
| `admin_profiles` | حسابات المدراء (مرتبطة بـ Supabase Auth) |

### نقطة أمان مهمة: ثمن الشراء سري

عمود `purchase_price` (ثمن الشراء/هامش الربح) موجود فقط في الجداول
الأصلية، وهذه الجداول محمية بـ **Row Level Security** بدون أي صلاحية قراءة
عامة. الواجهة العامة (والموقع) تقرأ فقط من views باسم `catalog_*`
(`catalog_products`, `catalog_categories`...) التي **لا تحتوي إطلاقاً** على
عمود ثمن الشراء. هذا يحمي الهامش السري حتى لو استُعملت واجهة Supabase
التلقائية (PostgREST) لاحقاً.

### البحث والسرعة

- فهارس `btree` على `category_id`, `status`, `slug`, إلخ.
- عمود `search_vector` (بحث نصي عبر `tsvector`) مع فهرس `GIN` على المنتجات،
  جاهز لبحث سريع حتى مع آلاف المنتجات.

## المنتجات التجريبية (Demo)

ملف `supabase/seed/seed_demo_products.sql` يضيف **3 منتجات تجريبية فقط**
(SKU يبدأ بـ `DEMO-`، والاسم يحمل بادئة "منتج تجريبي") لاختبار الأنبوب
الكامل من قاعدة البيانات إلى الواجهة. **يجب حذف هذه الصفوف قبل نشر أي
منتج حقيقي.** لا يوجد أي منتج حقيقي أو سعر حقيقي داخل هذا المستودع.

## التشغيل محلياً

### 1. المتطلبات

- Node.js 22+
- PostgreSQL 16 (محلي، أو مشروع Supabase حقيقي لاحقاً)

### 2. قاعدة البيانات

أنشئ قاعدة بيانات محلية وطبِّق ملفات الهجرة بالترتيب:

```bash
createdb tayssir_froid_dev
psql -d tayssir_froid_dev -f supabase/migrations/20260730000001_core_schema.sql
psql -d tayssir_froid_dev -f supabase/migrations/20260730000002_security.sql
psql -d tayssir_froid_dev -f supabase/seed/seed_demo_products.sql   # اختياري: بيانات تجريبية فقط
```

> **ملاحظة**: ملفات الهجرة تفترض وجود schema باسم `auth` مع جدول `auth.users`
> ودالة `auth.uid()` (تُنشئها Supabase تلقائياً في أي مشروع حقيقي). للتطوير
> على PostgreSQL عادي محلياً فقط، شغّل أولاً:
> `psql -d tayssir_froid_dev -f db/local-dev/00_bootstrap_supabase_like_roles.sql`
> — هذا الملف **لا يُستعمل أبداً مع Supabase الحقيقي**.

### 3. متغيرات البيئة

```bash
cp .env.example .env.local
# ثم عدّل DATABASE_URL ليطابق قاعدة بياناتك المحلية أو مشروع Supabase
```

### 4. تشغيل المشروع

```bash
npm install
npm run dev       # يفتح على http://localhost:3000
npm run typecheck # فحص TypeScript
npm run lint      # فحص ESLint
npm run build     # بناء الإنتاج
npm run test      # اختبارات الوحدة (Vitest)
```

## المراحل القادمة (بانتظار المراجعة والموافقة)

1. سلة الشراء (فرض الحد الأدنى 1000 درهم) وصفحة إتمام الطلب بدون حساب.
2. لوحة الإدارة: تسجيل دخول آمن، إدارة المنتجات/الصور/المخزون، حالات
   الطلب، تحديد عدد الكرطونات وحساب المجموع النهائي، طباعة الفاتورة
   وBon de préparation، استيراد/تصدير Excel-CSV.
3. ربط Supabase الحقيقي (قاعدة بيانات + تخزين الصور + تسجيل الدخول).
4. اختبارات شاملة، ثم النشر (دومين + استضافة تجارية) بعد موافقة صريحة.
